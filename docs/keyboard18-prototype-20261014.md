# 18键键盘原型

## 2.1.9 / 原型4：键面排版

修正字母键的 `useSpecialBackground` 标记，使用宿主字母键配色，继续尊重模块现有的外观设置。双字母以细空格分开；宽度权重调整为1.6，Shift/退格为1.3；第二行加入两个不响应输入的原生 `GAP`，形成对称缩进。私有码元、弹出字母和快捷操作仍按原编码处理，显示空格不进入解码器。

新增按单个18键字母键作用域执行的 Compose 外观 Hook：字号为宿主计算值的90%，保留其缩放；上方提示从右对齐改为居中。设置页同步采用提示在上、字母在下的字号层次和独立圆角键面。外观 Hook 解析失败时记录日志，输入引擎仍可安装。宿主绘制路径与接口依据见[外观接入分析](2026-10-14_逆向-18键外观-report.md)。

本地仅完成构建，GitHub 执行既有单元测试和签名构建；实际主题、按压和旋转效果需在手机确认。

## 2.1.8 / 原型3：首字母简拼和候选排序

用户实际输入 `WE → SD → M`，对应 `wsm`，按键顺序正确。旧版仅索引全拼，未将这组输入匹配到词库里已有的 `wei shen me / 为什么`，并且优先显示硬拼出的整串候选。本版新增每个音节首字母的独立索引，统一排序完整词语、组句、前缀候选和补全，降低重复单字组合的优先级，避免用极低词频条目拼出整句。

「为什么」可以使用简拼 `wsm`（`WE → SD → M`），也可以使用全拼 `weishenme`（`WE → WE → IO → SD → H → WE → BN → M → WE`）。简拼仍遵守组内字母约束，长按确定字母也保持约束。设置页提供这一输入示例。

新增5个使用实际打包词库的回归用例，覆盖正确简拼、全拼、错误字母组约束、删除恢复和低频单字排序。单元测试交由既有 GitHub 构建工作流执行，本地按用户要求只构建安装包，未进行真机验收。

## 2.1.7 / 原型2 修复

修复“开启并重启后仍显示26键”的一个确定接入错误：原型1按字段声明类型严格等于 `Context` 查找 `ab.p1` 的服务字段，而实际宿主 smali 声明为 `MiInputMethodService`。字段解析在所有18键宿主 Hook 安装之前失败，导致整个18键入口未安装。原型2按宿主服务类型匹配，并在 Application 初始化后将 Hook 安装、配置/词库读取和引擎创建的失败原因报告到18键设置页。

设置页现在还区分“18键布局已替换”和“当前不是标准26键布局”，便于定位后续问题。这些状态表示代码阶段结果，不能代替查看实际键盘。升级至2.1.7后重新启动输入法，在小爱中选择「拼音26键」。本地仍未连接可用的已授权测试设备，未声明真机验证通过。

本版新增图片中的 18 键字母布局、独立离线拼音解码、宿主候选栏接入，以及模块内可直接操作的键盘预览。**本地仅构建安装包，单元测试由 GitHub 工作流执行；未进行模拟器或真机功能测试，不能视为已经验收的日常版本。**

仅适配小爱 `com.xiaomi.type 0.2.1053.06f65b7c`（versionCode 21053）。默认关闭；设置变化需重启输入法。形码和18键模式互斥，启用一项会关闭另一项，原有形码码表和规则仍保留。

## 先看效果

安装模块原型 APK，打开首页「18键键盘 · 离线拼音 / 可交互预览」。下方预览使用与宿主相同的离线词库和解码器，能直接点按输入、点击候选、删除和切换中英文，无需先启用宿主 Hook。

预览界面包含输出编辑框、分组编码、横向候选列表和18键键盘。主页面沿用现有 `ShapeUiStyle` 的系统动态强调色、深浅色、平滑卡片和字号；预览字母键保持键盘的密集排列，键高至少56dp，宽度随屏幕及单双字母权重分配。单字母键的宽度可能小于通用页面按钮的48dp，属于按图实现密集键盘布局的取舍。没有新增固定时长的过场动画。

## 在小爱中启用

1. 在 LSPosed 启用模块，并勾选超级小爱输入法。
2. 打开模块的18键页面，开启「在小爱中启用18键」。
3. 点击「重启输入法并应用」，沿用项目已有的 Root 重启入口；也可以自行停止并重新打开输入法。
4. 在小爱中选择「拼音26键」。本模块接管该入口的中文布局和引擎。
5. 关闭18键开关并重启输入法可恢复原生输入。

模块内部复用 PINYIN/QWERTY 标识；宿主原生菜单仍显示「拼音26键」，模块设置页显示真实的18键选择。九键、手写、笔画和双拼布局不做18键转换。英文全键盘也转换成18键字母布局，保留原生英文引擎。平板分离布局保留原生布局；该场景下中文仍可能使用本模块的确定字母解码，未做运行检查。

## 按键行为

| 行 | 字母键 |
| --- | --- |
| 第一行 | Q / WE / RT / Y / U / IO / P |
| 第二行 | A / SD / FG / H / JK / L |
| 第三行 | Z / XC / V / BN / M，左右为 Shift 和删除 |

底部保留宿主原有的符号、数字、标点、空格、语言和回车控制。按键、工具栏和候选由宿主原生界面绘制，可以继续使用项目的外观设置；实际主题、按压反馈和旋转效果未测试。

| 操作 | 本版实现 |
| --- | --- |
| 中文点按字母键 | 输入该分组的一位编码，由离线引擎生成候选 |
| 长按字母键 | 使用原生弹出字符列表选择确定字母或该键的数字/符号；设置页预览使用选择对话框 |
| 点击候选 | 提交所选文字；选中的是输入前缀时，保留剩余编码继续组合 |
| 空格 | 有编码时提交首选；没有候选则明确输出可读分组编码，无编码时保留普通空格 |
| 删除 | 有编码时删除一位；空编码时沿用宿主编辑框删除。预览长按删除可清空预览 |
| 标点和数字 | 先提交当前组合内容，再输入对应字符 |
| Shift / 大写 | 沿用宿主状态；大写输入使用确定的首字母，长按可选择组内另一字母 |
| 英文 | 点按输入键帽的首字母，长按选择另一字母；使用宿主原英文引擎 |
| 回车和模式控制 | 模块先提交组合内容，再交回宿主处理发送、搜索、换行或模式切换 |
| Z / XC / V / BN / M 长按菜单 | 加入全选、复制、粘贴、段首、段尾；使用当前 InputConnection 的编辑操作 |

图片里没有提供手势细节，因此本版采用长按选择。没有实现左右或上下滑动输入。原生长按弹出、数字快捷输入及编辑快捷项的宿主事件路由都尚未运行验证；界面显示入口不代表对应宿主行为已验收。段首/段尾优先使用编辑框提取的文本定位，应用不支持提取时退回 Home/End。

分组编码使用私有码元保存，显示为 `[bn][io]ha[io]` 等可读形式，不把私有码元直接提交到编辑框。准确字母与分组输入分开处理；长按选择 `n` 会限制候选必须匹配 `n`，而点按 `BN` 可以匹配 `b` 或 `n`。

## 离线解码和数据

本版采用自有 Kotlin 解码器，没有引入 Rime native 引擎，也不依赖尚未证实的讯飞数组分组接口。

- 加载时把全拼编码和音节首字母简拼分别投影到18个分组码元，并建立独立 trie 索引。
- 每次输入按投影编码查找，同时保留确定字母和拼音分隔符约束。
- 使用有界词格组合连续字词，提供整串候选、前缀选词和少量词语补全。
- 每段最多保留8条组合路径；候选最多160项，全拼和简拼的每个同码词桶各取兼容输入的前48项。候选上限是原型的性能取舍，不是全部汉字覆盖的承诺。
- 输入最多64个码元，达到上限后显式提交当前组合，再接收下一位。
- 宿主选词记录本地词频，最多2048项；预览不写入宿主词频。重启读取已保存词频。

内置 **65,125** 条数据取自 [rime/rime-pinyin-simp](https://github.com/rime/rime-pinyin-simp/tree/0c6861ef7420ee780270ca6d993d18d4101049d0) 的 `pinyin_simp.dict.yaml`，上游说明其源自 AOSP PinyinIME。采用 Apache-2.0 许可，保留完整许可及来源说明到 APK 的 `assets/keyboard18/`。此处使用的是字典数据，不能把候选体验称为已复现 Rime 或讯飞。

固定上游提交：`0c6861ef7420ee780270ca6d993d18d4101049d0`。原字典 SHA-256：`e341598343a0f0f2035bb1aafc34a7f3bb7887deeecb3f60796262aaa2983e6b`。

处理方式：提取实际数据行，保留空格分隔的原拼音，去重文字/拼音对并保留最大权重，按权重排序，转为 UTF-8 TSV 和确定性 gzip。使用 `.table` 扩展名避免 AAPT 对 `.gz` 资源自动展开改名。

## 接入位置

- `Keyboard18Hook`：宿主 `ab.x0.b` 引擎创建、`ab.f1.c` 按键路由、`ab.s0.l` 原生拼音扩展，以及 `ab.p1.e/G/H` 布局生成和模式同步。
- `Keyboard18HostLayout`：反射构造宿主 KeyData、KeyRow、KeyboardLayout，重算字母区宽度，保留原控制行。
- `Keyboard18HostBridge`：复用现有 ShapeHostBridge 的接口结构校验，建立独立代理会话，转换候选、组合状态和选词结果。
- `Keyboard18Engine/Keyboard18Dictionary`：分组约束、查词、词格组合、候选选择、补全、删除和提交。
- `Keyboard18ContentProvider/Keyboard18Store`：独立开关、版本化状态报告及词库文件流；仅模块和宿主 UID 可调用，使用设备保护存储。
- `Keyboard18Activity`：设置及可交互预览，共用词库和解码器。

词库在宿主首次启用时同步加载，之后进程内共享、各会话独立保存输入状态。加载失败、版本不符或布局构造异常时保留原生路径。没有实测冷启动时间、按键延迟或内存占用。

## 构建和本次状态

```powershell
python -X utf8 scripts/update-keyboard18-table.py
.\gradlew.bat :app:assembleKeyboard18Prototype --console=plain
```

离线重建词库可给脚本传入 `--source-dir`，该目录需有上述固定提交的 `pinyin_simp.dict.yaml` 和 `LICENSE`。

输出目录：`app/build/outputs/apk/keyboard18Prototype/`。当前交付副本：`app/release/XiaoAiTypeUnblock-2.1.9-keyboard18-prototype4.apk`。正式签名安装包由 GitHub 工作流生成。

该构建类型优先使用配置的正式签名，否则使用开发签名。APK 与主模块使用同一 applicationId；覆盖安装要求签名一致，不能为了看预览自动移除已安装模块或其设置。

本地使用 `assembleKeyboard18Prototype` 完成资源处理、Kotlin 编译、打包及 release 的必要检查，不运行单元测试、宿主校验脚本、模拟器、ADB 安装或真机测试。既有 GitHub 工作流执行 `testReleaseUnitTest` 并构建正式签名 APK。

## 当前限制

这是可以安装和查看的实现原型，完整使用效果尚待后续验收。支持全拼及每个音节取一个首字母的简拼；暂未实现模糊拼音、拼写纠错、拼音反查、自造词及原生云候选。组句为有界词格排序，词频学习不是完整语言模型。未提供组合态内部精确光标编辑或滑动确定字母；输入框切换、组合文字重建、候选分页和工具面板往返需要实测。

关闭开关并重启输入法可恢复原生模式。仅完成构建不能据此标记为“完全可用”。
